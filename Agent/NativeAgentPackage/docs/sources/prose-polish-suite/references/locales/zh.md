# 中文润色政策

保留原文的简体或繁体、地区用词和语气。不默认把繁体转成简体，不把台湾、香港或大陆的术语强行统一。保留您/你、正式程度及作者立场；发现混用时先保留局部形式，不擅自选择全篇的地区标准。

## 检查项目

- 区分可能、能力、许可、义务和建议：「可能」「可以」「能够」「应该」「必须」「不必」「不得」不可随意互换。不为减少所谓套话而去掉必要的情态词。
- 「不一定」「并非所有」「未必」「尚未」「不再」的否定范围和时间不同。「最多」「至少」「仅」「除非」不能为了简洁而删除。
- 保留「了」「过」「着」「一直」「曾经」「正在」表达的完成、经历、持续和进展。「已经准备检查」不等于「已经检查」。
- 保留「据称」「研究发现」「观察到」「推测」等信息来源和认知行为。转述不能改成作者亲自确认的事实。
- 可把「进行检查」改为「检查」，但要保留时态、主体、对象、条件和语气。「能够进行检查」不能变成已经完成检查。
- 处理多层定语、主语切换、搭配和指代不清时，不猜测省略的主体。主动/被动转换不能改变责任主体或信息焦点。
- 「因此」「同时」「此外」「不过」分别可能表示因果、同时、递进和转折，不按出现次数替换。真实的三项要求和排比必须保留。
- 「赋能」「生态」「闭环」「抓手」可能空泛，也可能是精确的业务术语。检查当前语义，不使用一刀切禁词表，不制造近义词轮换。
- 「的」「地」「得」按句法和语境判断。标点须匹配原文地区与体裁，不用英文句长或标点配额评判中文。
- 直接引语、书名、人名、数字、URL、代码和注释保持原样。技术文档的 `raise` 等操作不要为了口语化改变概念。尤其要区分重新抛出同一个异常与创建、引发一个新异常；仅保留异常名称不足以保留操作身份。
- 普通话润色不等于粤语改写。若原文有粤语口语成分，应保留；该方言的全面质量尚未验证。
- 中文页面中的整段外语保持原样，不自动翻译。事实或代码解释疑似有误时，不用润色暗中纠错。

## 对照例

| 原文 | 不安全的变化 | 原因 |
|---|---|---|
| 并非所有请求都失败了。 | 所有请求都没有失败。 | 部分否定→全部未失败 |
| 最多执行一次。 | 执行一次。 | 上限→实际次数 |
| 可以不提交。 | 不可以提交。 | 许可不做→禁止做 |
| 据称系统已经恢复。 | 系统已经恢复。 | 删除消息来源 |
| 請先儲存檔案。 | 请先保存文件。 | 未经要求转换字形及地区词 |

选词时先确定对象：金额不是数量，用户不是管理员，例外的类别不是触发原因。「有效」与「高效」也不能仅凭顺口互换。
