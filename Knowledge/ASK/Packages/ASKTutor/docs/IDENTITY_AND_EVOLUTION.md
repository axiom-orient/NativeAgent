# ASKTutor — 정체성과 발전 원칙

## 정체성

ASK의 근거 지식을 사용하는 learner/session/practice/evaluation/plan·insight domain SDK다. caller는 TutorKernel을 명시 model/store와 조립하는 앱 개발자다. 학습 UI와 계정은 host 책임이다. NativeAgent 실행 원장·ASK 지식 truth를 대체하는 앱은 비목표다.

## 변하면 안 되는 것

학습 상태와 지식 승인/정본을 분리한다. source evidence identity와 learner/session 경계를 지킨다. insight 적용 뒤 post-commit 실패는 이미 확정된 결과와 후속 실패로 구분한다. 모델 평가를 권한이나 객관적 진실로 승격하지 않는다.

## 변경 가능한 것

동일 domain 입력·상태 전이·오류·데이터 보존 의미를 지키는 model gateway/store/UI adapter는 교체할 수 있다. public composition과 ASK knowledge 경계의 변경은 실제 consumer 계약 검토를 요구한다.

## 발전 방향

학습 과제·피드백과 정확한 지식 근거의 연결, 관찰 가능한 학습 상태와 안전한 insight 환류를 우선한다. 선택 SDK로 유지하고 채팅/session/정본 writer를 무분별하게 통합하지 않는다.
